# Particle compatibility fixtures

The native sample files record results from local Garry's Mod x64 tests against self-authored particle definitions. They contain numeric measurements, not game assets. The tiny PCF fixtures are authored for these tests.

- `spritecard_native_samples.json`: sixteen valid SpriteCard cases, captured against a black render target using a self-authored four-color texture atlas. Sample ages are derived from the known particle velocity. Covers independent sequences, frame interpolation, animation rates, FPS mode, lifetime fitting and max-luminance blending. Both simulation-clock and GPU-pixel regressions use these measurements.
- `position_native_samples.json`: effects created at control point `(100, 0, 64)`, with no position initializer, a zero-offset box, or a box offset by ten units. Native render bounds are relative to the effect origin. All three cases visibly rendered the expected red sprite. A missing initializer leaves the particle at world origin.
- `group_cases.pcf` and `group_native_samples.json`: a moving parent, with a child offset by one hundred units, across matching and nonmatching control point groups. Group zero matches only zero. The regression compares child bounds relative to the simultaneously captured parent baseline, separating group propagation from render-frame timing jitter.

`src/operator_parameters.tsv` is a compatibility catalog of functional operator names, parameter names and DMX types observed in the local game's registration metadata on 2026-11-06. It contains no executable code or game binary data. The `*` group contains sixteen shared timing parameters; the other 160 groups contain operator-specific parameters. Numeric tags use DMX scalar type identifiers. The catalog does not replace imported attributes, define defaults, or reject unknown extensions. Native tests confirmed that mismatched scalar types can be ignored by the game despite displaying in the preview; authoring normalizes supported numeric conversions and validation reports imported mismatches.

- `rotation_cases.pcf` and `rotation_native_samples.json`: twelve initializer cases for constant offsets, positive/negative velocities, direction flipping and zero random exponents. A native scalar-to-vector initializer reads rotation or rotation speed into a position measurement. The simulation test removes that measurement initializer and checks the resulting rotation, using `Rotation Basic` to observe velocity.
- `yaw_cases.pcf` and `yaw_native_samples.json`: eight rendered silhouettes covering yaw, roll and yaw flipping. The native yaw is measured on the same rendered particle by mapping field 12 into its position, so the reference records the actual angle rather than assuming a random initializer chose a particular direction. Each sample records covered pixel spans on all 128 rows. The GPU test uses the game's pixel grid and the same 60-degree field of view.
