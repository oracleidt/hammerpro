# Particle compatibility fixtures

The native sample files record results from local Garry's Mod x64 tests against self-authored particle definitions. They contain numeric measurements, not game assets. The tiny PCF fixtures are authored for these tests.

- `cp_default_frame_cases.pcf` and `cp_default_frame_native_samples.json`: nine local velocity cases (three axes on each of CP 0, 1 and 2), recorded over 44 fixed simulation steps. CP 0 has an explicitly assigned identity frame; CP 1 and 2 have no assigned orientation. All control-point positions are zero, so render bounds directly expose the moving particle. The regression checks all 1,188 coordinate values bit for bit, including the native secondary frame (forward +Y, left −X, up +Z).

- `spritecard_native_samples.json`: sixteen valid SpriteCard cases, captured against a black render target using a self-authored four-color texture atlas. Sample ages are derived from the known particle velocity. Covers independent sequences, frame interpolation, animation rates, FPS mode, lifetime fitting and max-luminance blending. Both simulation-clock and GPU-pixel regressions use these measurements.
- `position_native_samples.json`: effects created at control point `(100, 0, 64)`, with no position initializer, a zero-offset box, or a box offset by ten units. Native render bounds are relative to the effect origin. All three cases visibly rendered the expected red sprite. A missing initializer leaves the particle at world origin.
- `group_cases.pcf` and `group_native_samples.json`: a moving parent, with a child offset by one hundred units, across matching and nonmatching control point groups. Group zero matches only zero. The regression compares child bounds relative to the simultaneously captured parent baseline, separating group propagation from render-frame timing jitter.

`src/operator_parameters.tsv` is a compatibility catalog of functional operator names, parameter names and DMX types observed in the local game's registration metadata on 2026-11-06. It contains no executable code or game binary data. The `*` group contains sixteen shared timing parameters; the other 160 groups contain operator-specific parameters. Numeric tags use DMX scalar type identifiers. The catalog does not replace imported attributes, define defaults, or reject unknown extensions. Native tests confirmed that mismatched scalar types can be ignored by the game despite displaying in the preview; authoring normalizes supported numeric conversions and validation reports imported mismatches.

- `rotation_cases.pcf` and `rotation_native_samples.json`: twelve initializer cases for constant offsets, positive/negative velocities, direction flipping and zero random exponents. A native scalar-to-vector initializer reads rotation or rotation speed into a position measurement. The simulation test removes that measurement initializer and checks the resulting rotation, using `Rotation Basic` to observe velocity.
- `yaw_cases.pcf` and `yaw_native_samples.json`: eight rendered silhouettes covering yaw, roll and yaw flipping. The native yaw is measured on the same rendered particle by mapping field 12 into its position, so the reference records the actual angle rather than assuming a random initializer chose a particular direction. Each sample records covered pixel spans on all 128 rows. The GPU test uses the game's pixel grid and the same 60-degree field of view.

- `color_light_cases.pcf` and `color_light_native_samples.json`: 30 color initializer cases captured at one fixed point in `gm_construct`. The numeric reference includes the particle and control-point lighting queries, clamp/amplification order, four tint blend modes, extrapolated bias, native 8-bit lighting quantization, inverted clamp bounds and a second tint control point. No map assets are included.
- `color_fade_cases.pcf` and `color_fade_native_samples.json`: four constant-color/fade cases rendered with the self-authored gray texture. Positions encode particle age independently of wall-clock timing. Core and GPU regressions check all captured ages. Native vertex colors use gamma 2.2, while the texture is sampled as sRGB.

- `cap_cases.pcf` and `cap_native_samples.json`: seven requested system sizes from 128 to 9,000. A sequential initializer lays particles along a measured path. After spawning, the remote control point is reset so its bounds no longer hide the particle bounds. Native requests above 5,000 stop at the same particle position; the simulation checks that cap and accumulated floating-point path increments.
- `path_edge_cases.pcf` and `path_edge_native_samples.json`: seven sequential path cases with zero, negative, one, integer and fractional mapping counts, including bounce mode. The native reference records bounds after resetting the remote control point.

- `cp_position_time_native_samples.json`: 300 native control-point time queries across CP 0, 1 and 63, checking 900 coordinate bit patterns, zero timestep, past clamping and future extrapolation. `cp_birth_{box,sphere,ring,path}_cases.pcf` and matching native samples record nine moving-control-point effects per shape over 59 fixed steps. Delayed bursts and continuous rates use root and secondary points; all 5,844 measurable particle coordinates are compared bit for bit. No-particle frames are checked separately from control-point render bounds.

- `alpha_simple_native_samples.json`: 600 native four-lane cases (2,400 alpha values) for simple fade-in/out, with original/current opacity, varied lifetime windows, negative and zero durations, and common strengths. Both native simple fades ignore the strength amplitude. `alpha_simple_live_cases.pcf` and its native samples check 1,788 alpha bit patterns over 149 game frames, including stacked operator order, delayed activation and deactivation. Readback first resets position X, then copies alpha into X, avoiding cancellation against the previous frame’s position. Those two measurement operators are removed when replaying the actual fades in the simulator.

- `alpha_random_operator_native_samples.json`: 480 native four-lane cases (1,920 values) for random fade-in/out, including per-particle table samples, quarter-power exponents, active operator offsets, absolute/proportional time, smooth/rational fade-out curves, zero bias and zero durations. `alpha_random_live_cases.pcf` and its samples compare 1,788 game alpha values with fixed durations and different curves, ordering and gates. `alpha_random_pool_cases.pcf` and its samples add six 4,096-particle effects with variable duration ranges: all table strata occur once regardless of the game’s collection seed, allowing 894 population maxima to be compared exactly. Readback resets X before copying alpha, as in the simple fade fixtures.

- `radius_scale_operator_native_samples.json`: 480 native four-lane cases (1,920 radius values), including original/current radii, rational bias, smoothing, exclusive end times, empty windows, zero/negative lifetimes and signed output. `radius_scale_live_cases.pcf` and its samples compare 1,788 game readbacks across 149 frames, including ramps before/after scaling, two scale operators and radius oscillation through zero. Radius is one current attribute with a separate initial snapshot. Signed cases repeat the readback’s floating-point range transform before comparison; positive cases expose the radius directly.

- `remap_scalar_operator_native_samples.json`: 900 native scalar remap values, checking endpoint limits, equal/reversed ranges, current attribute reads and strength overshoots. `remap_scalar_live_cases.pcf` and its samples check 2,384 live game values over 149 frames: position remapping before/after movement, unclamped alpha strength blending and signed radius changes. Two radius cases read a preceding alpha fade in the same frame. Position cases have no readback operators; other cases remove only the last two readback operators during replay. Attributes requiring unavailable vector storage remain reported as unsupported. Creation-time writes from an initializer or an operator, changing birth times and raw negative alpha2 strength blends are covered by four additional cases.

- `sequence_scalars_live_cases.pcf` and its native samples check 1,043 game values from seven effects over 149 frames. Sequence 9 and 13 preserve fractional initializer and operator values; a fractional sequence ramp is read back through radius. The sequence-73 initializer case resets the rendering selection after measuring the attribute, testing the numeric limit without assuming the texture has that sequence. Public integer selection edits remain compatible while internal scalar values retain float precision.
