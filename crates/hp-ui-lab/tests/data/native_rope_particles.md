# Native rope particle references

These are owned fixtures, not user map assets. The generator writes the PCF and a GMA containing two authored 16x16 textures and UnlitGeneric/SpriteCard materials. The Lua hook mounts the GMA and renders actual PCF systems in Garry’s Mod into a 128x128 HDR target, then captures its readback. No particle attributes or native instructions are modified.

The path initializer emits three points after 0.1 seconds. CP0/CP1 positions and CP0 orientation are set before emission; capture waits at least 0.3 seconds. Cases cover CPU and SpriteCard ropes, straight/curved paths, subdivisions 1/3/6, texel sizes 1/4, texture offset, particle color/alpha and varying width. A second owned game launch reproduced all sixteen PNGs byte for byte. The first private birth-at-zero experiment was superseded and is not included.

The UI test reads the unchanged PCF and actual GMA, simulates its authored initializers, preserves ribbon order through the production sprite conversion, and compares both viewport and particle-preview GPU paths: 32 whole images. Coverage must match exactly. The usual encoded RGB tolerance is 3/255. A highly minified repeated SpriteCard texture may have at most two exceptional pixels per 16,384-pixel image, each bounded by 16/255 encoded RGB and 3/255 in linear RGB. This records small interpolation/filtering differences between the D3D9 reference and WGPU instead of changing curve geometry to fit isolated texels. The test prints both maxima; it does not claim bit-identical final images.

CPU ropes duplicate endpoint controls, interpolate byte color/alpha and width, join neighboring segment sides, and divide world-distance UVs by texture height times texel size. SpriteCard ropes extrapolate endpoint controls, evaluate Catmull-Rom position/radius and tangent in the vertex shader, and multiply world-distance UVs by texel size. Their byte modulation changes at the next original point, except at the final end pair. The two vertex orders use different quad diagonals. Bilinear rope sampling is separate from the ordinary sprite sampler.

The public Valve shader is useful mathematical context: [splinecard_vsxx.fxc](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/materialsystem/stdshaders/splinecard_vsxx.fxc). The installed native vertex-builder output is the authoritative reference for PCF parameter behavior and UV quirks.
