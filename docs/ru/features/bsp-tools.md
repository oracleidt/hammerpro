# Инструменты BSP

Инструменты для работы со скомпилированными картами и архивами: декомпилируйте BSP обратно в редактируемую карту, просмотрите pak-файл BSP, GMA или VPK (и отредактируйте pak-файл и объекты BSP), экспортируйте геометрию карты как OBJ для 3D-инструментов и сравните две карты.

<a id="bsp-decompiler"></a>
## Декомпилятор BSP

**Файл > Импорт > BSP Декомпилятор...** запрашивает `.bsp` и перестраивает из него редактируемую карту в духе BSPSource. Работа выполняется в фоновом режиме (*Декомпиляция карты...*), и результат открывается на новой вкладке (*карта декомпилируется за N мс (браши: N, объекты: N). Сохраните ее как VMF, чтобы сохранить ее.*).

Что возвращается:

- мировые браши с их текстурными осями и масштабами карт освещения (названия материалов, исправленные компилятором, возвращаются к оригиналам);
- чистить объекты своими брашами; Детальные браши становятся объектами `func_detail`, по одному на группу соприкасающихся брашов;
- дисплейсменты, статические пропы (`prop_static`), наложения (`info_overlay`, с гранями, на которых они лежат), кубические карты (`env_cubemap`), окклюдеры и браши площадного портала;
- объекты с их выходами и идентификаторы из `hammerid`.

Материалы и модели из pak-файла карты копируются в папку кэша, которая монтируется, когда карта открыта, поэтому отображается ее собственное содержимое (*Файлы собственного содержимого карты, отображаемые, когда она открыта*).

Скомпилированная карта не может вернуть все обратно: экземпляры объединены, визгруппы, группы и скрытые объекты исчезли, а браши подсказок, пропуска и исходных брашов были удалены компилятором. Браши, которые компилятор оставляет в файле, не используя их (объём `func_occluder`, который вместо этого восстанавливается из данных окклюдеров), пропускаются, а неиспользуемые браши `tools/toolstrigger` объектов `func_viscluster` возвращаются каждый как отдельный `func_viscluster`. Водные наложения (береговые линии) возвращаются как объекты `info_overlay_transition` с полосами карты. В консоли перечислены браши, дисплейсменты и окклюдеры, которые не удалось перестроить, наложения, потерявшие свои грани, и браши без граней (карта, защищенная от декомпиляции, см. [Защитите свой BSP](bsp-protection.md)).

Декомпилятор BSP работает с файлом `.bsp`, который у вас уже есть. Чтобы восстановить карту с сервера Garry's Mod, к которому вы присоединились, см. [BSP Sniffer](bsp-sniffer.md).

<a id="open-an-archive-pack-inspector"></a>
## Открыть архив (инспектор пакетов)

**Файл > Импорт > Открыть архив...** открывает окно **Инспектора пакетов** на `.bsp`, `.gma` или `.vpk` (**Открыть...** в окне выбирается другое). Если поместить один из этих файлов в окно Hammer Pro, он также откроется там.

В заголовке показано, что представляет собой архив: для BSP его **Версия**, **Редакция**, количество **Объектов**, Размер **Pakfile** и **Сжатые блоки**; для GMA это **Название**, **Тип**, **Теги** и **Версия**; для VPK это **Версия**.

| Контроль | Описание |
| --- | --- |
| **Фильтровать записи...** | Фильтрует список файлов. |
| **Извлечение...** | Извлекает выбранную запись или каждую запись в списке, если ни одна не выбрана, в выбранную вами папку. |
| **Добавить файлы...** (BSP) | Добавляет файлы в pakfile. |
| **Заменить...** (BSP) | Заменяет выбранную запись файлом. |
| **Удалить** (BSP) | Удаляет выбранную запись. |
| **Единый объект** (BSP) | Показывает объединение объектов в виде текста, который можно редактировать (он должен начинаться с `worldspawn`). |
| **Сохраните BSP** (BSP) | Записывает ваши изменения после подтверждения (**Переписать BSP?**): новый файл заменяет старый после завершения. Сохраните копию, если вам может понадобиться старая версия. |
| **Отменить** | Удаляет ожидающие изменения (*N для добавления, N для удаления*). |

Выберите запись для предварительного просмотра: текстовые файлы (VMT, TXT, Lua, RES, CFG, JSON, VMF, RAD, FGD, VCD...), текстуры VTF (размер, формат, MIP-карты, кадры и изображение), изображения PNG, JPG, TGA и BMP, заголовки MDL (версия, текстуры, скины, кости), файлы WAV (каналы, скорость, биты) и файлы частиц PCF (их системы). Записи, которые использует открытая карта, отображаются зеленым цветом (из последнего анализа окна выпуска).

<a id="export-obj"></a>
## Экспорт OBJ

**Файл > Экспорт > Экспорт OBJ...** записывает геометрию браши и дисплейсмента карты с координатами текстуры в файл `.obj` и библиотеку материалов `.mtl` рядом с ним для 3D-инструментов (Blender, средство просмотра моделей...). Грани с текстурами `tools/` исключены. Чтобы пройти туда и обратно с помощью Blender и вернуть его на карту, используйте вместо этого ссылку [Blender](blender.md). Координаты переворачиваются от буквы Source до буквы Y, как ожидается большинством 3D-инструментов. Размеры текстур берутся из игрового контента, если они известны (в противном случае : 512). Файлы записываются атомарно.

<a id="compare-two-maps"></a>
## Сравните две карты

**Карта > Сравнить с другой картой...** перечислены различия между открытой картой и другой VMF (более старая версия, автосохранение, копия). См. [Проверить наличие проблем](check-problems.md) для окна **Сравнить карты**.

<a id="mcp"></a>
## MCP

`decompile_bsp`, `inspect_archive` и `export_obj` предоставляют приложениям AI одинаковые инструменты. См. [справку по инструменту MCP](../MCP.md).

<a id="tips"></a>
## Советы

- Используйте инспектор пакетов в GMA вашего выпуска, чтобы проверить, что вы отправляете, перед публикацией.
- Декомпиляция отлично подходит для восстановления потерянного VMF вашей собственной карты; сразу сохраните его как VMF.
- Экспортируйте OBJ, чтобы создать фон или модель в 3D-инструменте, который точно соответствует вашей карте.

<a id="faq"></a>
## Частые вопросы

**Могу ли я редактировать GMA или VPK в инспекторе пакетов?** Нет, редактировать можно только Pak-файл BSP и блок объектов. Файлы GMA и VPK доступны только для чтения (извлечение и предварительный просмотр).

**Идентична ли декомпилированная карта оригиналу?** Нет. Геометрия и объекты возвращаются, но экземпляры, группы, визгруппы, скрытые объекты и браши, доступные только для компилятора, теряются.

**Откуда берутся собственные материалы декомпилированной карты?** Из pak-файла, скопированного в папку кэша, смонтированную при открытой карте.
