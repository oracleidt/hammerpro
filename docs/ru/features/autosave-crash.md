# Автосохранение и восстановление после сбоя

Hammer Pro сохраняет копии ваших измененных карт в фоновом режиме, сохраняет их снова в случае чрезвычайной ситуации, когда что-то идет не так, предлагает восстановить автосохранение, более новое, чем карта, которую вы открываете, и записывает отчет о сбое, который вы можете отправить разработчикам. Файл журнала записывает каждый запуск.

<a id="autosave"></a>
## Автосохранение

Каждые несколько минут каждая открытая карта с несохраненными изменениями записывается в новый файл автосохранения в фоновом режиме (в консоли отображается **Автосохранено**). Сам файл карты никогда не трогается. Копия включает камеры карты. Карта копируется по несколько миллисекунд между кадрами, поэтому даже огромная карта автосохраняется без подтормаживаний; изменение во время копирования начинает его заново (выделение объектов его не перезапускает). **Сохранить** (`Ctrl+S`) тоже записывает файл карты в фоне: закрытие карты или Hammer Pro ждет окончания этой записи, а **Сохранить как...**, сделанное в это время, сохраняет новый файл.

Установите его в **Настройки > Общие**, раздел **Автосохранение**:

| Параметр | Описание | По умолчанию |
| --- | --- | --- |
| **Сохранять все** | Минуты между автосохранениями, от 0 до 120. 0 отключает автосохранение (**Отключено**). Ключ `edit.autosave_minutes`. | 5 минут |
| **Копии сохраняются на каждой карте** | Автосохранения сохраняются для каждой карты, от 1 до 100; самые старые удаляются. Ключ `edit.autosave_keep`. | 10 |

На странице отображается папка: *Автосохранения хранятся в ...*. В Windows это `%LOCALAPPDATA%\HammerPro\autosave`. Файлы называются `<map>_<hash>_<time>.vmf`, где хэш соответствует полному пути к карте: две карты с одинаковым именем в разных папках никогда не используют общие копии.

Автосохранения представляют собой обычные файлы VMF: откройте их с помощью **Файл > Открыть карту...**, как любую другую карту.

<a id="recovering-an-autosave"></a>
## Восстановление автосохранения

Когда вы открываете карту с автосохранением новее, чем файл (работа, которую вы не сохранили), Hammer Pro спрашивает **Восстановить автосохранение?** (*Найдено автосохранение новее, чем карта. Открыть его?*), с именем автосохранения:

| Кнопка | Описание |
| --- | --- |
| **Откройте автосохранение** | Вместо этого открывает автосохранение (*Автосохранение открыто. Сохраните, чтобы сохранить его.*). |
| **Сохраните сохраненную карту** | Открывает файл карты как есть. |
| **Откройте папку автосохранения** | Показывает папку автосохранений. |

Если вы закрыли карту с помощью **Не сохранять**, ее автосохранение до этого момента не предлагается: вы намеренно выбросили эту работу (файлы остаются до тех пор, пока вращение не удалит их).

<a id="emergency-saves"></a>
## Экстренное сохранение

- Когда ошибка останавливает кадр редактора, измененные карты сохраняются рядом с автосохранениями до того, как будет написан отчет о сбое, и в отчете указывается, где именно.
- При потере графического устройства (сброс драйвера, удаление GPU) измененные карты каждой вкладки сохраняются рядом с автосохранениями, а Hammer Pro предлагает перезапустить: **Да** запускает его снова со всеми вашими вкладками, измененные карты открываются с сохраненными изменениями. См. [Графическое устройство потеряно] (../troubleshooting/graphics-device-lost.md).
- Когда компьютеру не хватает памяти, Hammer Pro использует небольшой резерв для продолжения работы, сразу сохраняет измененные карты и просит вас освободить память. См. [Недостаточно памяти](../troubleshooting/out-of-memory.md).
- В консоли отображается графическая ошибка, которая может испортить только один кадр (*Графическая ошибка (один кадр был пропущен)*), и Hammer Pro продолжает работать; больше из них попадают в файл журнала.

<a id="crash-reports"></a>
## Отчеты о сбоях

При сбое Hammer Pro он записывает отчет (сообщение, местоположение, поток, обратную трассировку и последние строки журнала) в `crash-<date>.txt` в папке сбоя, `%APPDATA%\HammerPro\crash` в Windows. Сохраняются 10 новейших отчетов.

При следующем запуске окно **Hammer Pro неожиданно закрылось** показывает это один раз:

| Контроль | Описание |
| --- | --- |
| **Файл отчета:** | Где находится отчет. |
| **Показать файл отчета** | Открывает свою папку с выбранным отчетом. |
| **Скопировать отчет** | Копирует текст в буфер обмена, чтобы вставить его в сообщение. |
| **Открыть сохраненные изменения** | Открывает аварийное сохранение, если оно есть (*Ваши несохраненные изменения были сохранены в ...*). |

Сбой вне кода Rust (нарушение прав доступа в графическом драйвере, переполнение стека) или выделение, которое невозможно обслужить, тоже пишет отчет с указанием модуля, в котором это произошло, и последних строк журнала; когда это происходит в фоновом потоке, сначала сохраняются измененные карты. Сбои, которые не оставляют возможности что-либо записать (процесс убит), тоже отлавливаются: каждый запуск оставляет маркер, который удаляется при обычном закрытии, а следующий запуск превращает маркер, оставленный мертвым процессом, в отчет с концом журнала предыдущего запуска.

Ошибки в фоновых потоках не закрываются Hammer Pro: они протоколируются, и первые несколько запусков также получают файл отчета (не предлагается при следующем запуске), путь к которому указан в журнале.

Запуски, начатые с `--script` или `--screenshot`, никогда не читают и не записывают папку сбоя.

<a id="log-file"></a>
## Файл журнала

Каждый запуск записывает `hammerpro.log` построчно в папку журналов, `%LOCALAPPDATA%\HammerPro\logs` в Windows. Предыдущий запуск сохраняется как `hammerpro.old.log`. Предупреждения и ошибки также отображаются в консоли редактора. Прикрепите журнал к отчету об ошибке (см. [Сообщение об ошибках](../troubleshooting/reporting-bugs.md)).

<a id="tips"></a>
## Советы

- Уменьшите значение **Сохранять каждые** до 1-2 минут в больших сеансах, если ваша машина быстрая; сохранение происходит в фоновом режиме.
- После сбоя нажмите **Копировать отчет** и вставьте его в отчет об ошибке: в нем есть все, что нужно разработчикам.
- Используйте **Карта > Сравнить с другой картой...** при автосохранении, чтобы увидеть, что изменилось, прежде чем восстановить карту.

<a id="faq"></a>
## Частые вопросы

**Автосохранение перезаписывает мою карту?** Нет. Автосохранения сохраняются в отдельной папке; только **Сохранить** записывает файл карты.

**Сохраняются ли автоматически карты без названий?** Да, каждая открытая карта с несохраненными изменениями сохраняется автоматически.

**Я отключил автосохранение и потерял работу.** Установите для **Сохранять все** значение выше 0; Экстренные сохранения по-прежнему происходят при сбое, но регулярные автосохранения : это ваша подстраховка.
