# Обновления

Hammer Pro ищет новый выпуск на GitHub при запуске, сообщает вам, что нового, и устанавливает его для вас: он загружает выпуск, закрывается, заменяет `hammerpro.exe` там, где он установлен, и запускается снова. Пока вы не нажмете **Обновить**, ничего не будет загружено.

<a id="what-happens-at-startup"></a>
## Что происходит при запуске

1. Сразу после открытия окна фоновый поток запрашивает у GitHub Releases API проекта Hammer Pro (`oracleidt/hammerpro`, последняя версия) новейший тег, например `v1.0.3`.
2. Тег сравнивается с версией, которую вы используете, номер за номером (`1.0.10` новее, чем `1.0.9`).
3. Если версия более новая, откроется окно **Доступно обновление**. В противном случае ничего не отображается.

Проверка никогда не блокирует редактор и никогда не выдаёт ошибок: без сетевого подключения, за брандмауэром или когда GitHub работает медленно, редактор просто запускается как обычно. Автоматические прогоны (`--script`, `--screenshot`, `--bench-open`) никогда не проверяют.

<a id="the-update-available-window"></a>
## Окно Доступное обновление

| Часть | Что это показывает |
| --- | --- |
| Строка заголовка | *Hammer Pro Доступна версия 1.0.3* и *Вы используете версию 1.0.2.* |
| **Что нового** | Примечания к релизу (описание на GitHub), прокручиваемые. Заголовки, маркированные списки и простые абзацы форматируются. |
| **Обновление** | Скачивает архив релиза и устанавливает его (см. ниже). |
| **Игнорировать** | Закрывает окно. Если установлен флажок **Больше не показывать**, эта версия пропускается: окно для нее больше не открывается при запуске и возвращается для следующей версии. |
| **Больше не показывать** | Запоминает версию в настройках `update.skipped_version`. Ручная проверка (**Проверить наличие обновлений...**) по-прежнему показывает это. |

Если в выпуске нет архива Windows, в окне предлагается **Открыть страницу выпуска** вместо **Обновить**.

<a id="linux-and-macos"></a>
## Linux и macOS

Готовые сборки Hammer Pro публикуются **только для Windows**. В Linux, macOS или любой другой системе соберите Hammer Pro самостоятельно для своего дистрибутива или Mac (см. [Сборка из исходного кода](../development/building.md)).

Сборка из исходного кода никогда не устанавливает выпуск сама, потому что архив выпуска содержит программу для Windows. Новые версии она всё равно проверяет: когда выходит новая версия, окно сообщает об этом и вместо кнопки **Обновить** показывает команды обновления. В папке вашего клона выполните:

```bash
git pull
cargo build --release -p hammerpro
```

Затем запустите новую сборку из `target/release`. Новый клон тоже подойдёт, если ваша копия старая или изменена. Через MCP `get_update_status` возвращает `self_install: false` с этими командами, а `apply_update` отказывает с тем же советом.

<a id="installing"></a>
## Установка

1. **Обновление** загружает `HammerPro-<version>-windows.zip` во временную папку с индикатором выполнения и кнопкой **Отмена**. Загрузка проверяется до того, как что-либо будет закрыто: ее размер, ее контрольная сумма SHA-256 по сравнению с той, которую GitHub публикует вместе с выпуском (если она есть), и архив должен содержать `hammerpro.exe`. Несовпадающая загрузка удаляется и отклоняется.
2. Hammer Pro затем закрывается, как **Файл > Выход**: если на карте есть несохраненные изменения, вас попросят сначала сохранить, отменить или отменить. **Отмена** оставляет сеанс открытым и ожидает загрузки загруженного обновления (в окне предлагается **Перезапустить и установить**). Обновление не запускается во время компиляции.
3. Небольшой помощник (копия `hammerpro.exe`, запущенная из временной папки без окна) ждет завершения программы. Он еще раз проверяет контрольную сумму архива (файл, измененный после загрузки, отклоняется), извлекает только новый `hammerpro.exe` (какие бы другие имена ни содержал архив, ничего не пишется в другие места) рядом со старым, переименовывает старый в `hammerpro.exe.old` (сохраняет в качестве резервной копии), помещает новый на его место, повторяя попытку, пока Windows держит файл заблокированным, затем запускает новый `hammerpro.exe`. Он никогда не закрывает ваши другие окна Hammer Pro и мосты `hammerpro.exe --mcp` ваших AI-приложений: Windows позволяет переименовать работающую программу, поэтому они продолжают работать из старого файла, пока вы их не закроете. Если более старый `hammerpro.exe.old` еще используется, он откладывается под именем `hammerpro.exe.old-<число>` и удаляется при одном из следующих запусков.
4. Если что-то не получается (файл остается заблокированным, диск переполнен, архив поврежден), старая программа устанавливается обратно, окно ошибки объясняет, что произошло, и старая Hammer Pro запускается заново. Ваши настройки не тронуты.

Программа заменяется **в том же месте**, что и та, которую вы запускали, поэтому копия, установленная в любом месте (Рабочий стол, `D:\Tools\HammerPro`...), обновляется на месте. Если для этой папки требуются права администратора (например, `C:\Program Files`), обновление завершается успешно и сообщает об этом; запустите Hammer Pro из папки, в которую вы можете писать.

<a id="settings--updates"></a>
## Настройки > Обновления

**Инструменты > Параметры...** (`Ctrl+,`), страница **Обновления**:

| Параметр | Описание | По умолчанию |
| --- | --- | --- |
| **Проверка обновлений при запуске** | Включает или выключает проверку данных при запуске. Ключ `update.check_on_startup`. | на |
| **Показывать окно обновления при выходе новой версии** | Главный выключатель окна. Включите его снова, чтобы отменить действие **Больше не показывать**, какую бы версию вы ни скрыли: при этом удаляется и пропущенная версия. Ключ `update.show_dialog`. | на |
| **Проверьте наличие обновлений прямо сейчас** | Сразу проверяет и открывает окно, когда существует более новая версия (или сообщает, что вы обновлены). | |
| **Показать обновление** | Снова открывает окно найденного обновления. | |
| Строка состояния | *Hammer Pro обновлена (последняя версия: 1.0.2)*, *Доступна версия 1.0.3.* или причина, по которой последняя проверка не удалась. | |
| **Пропущенная версия** и **Хватит пропускать** | Отображается, когда вы установили флажок **Больше не показывать**. Ключ `update.skipped_version`. | пустой |

**Справка > Проверить наличие обновлений...** (и палитра команд) выполняет то же самое, что и **Проверить наличие обновлений**.

<a id="for-testing-the-hp_update-variables"></a>
## Для тестирования: переменные HP_UPDATE.

Две переменные среды позволяют вам опробовать весь процесс без реального выпуска:

| Переменная | Эффект |
| --- | --- |
| `HP_UPDATE_API_URL` | Заменяет адрес GitHub. Направьте его на локальный HTTP-сервер, который ответит JSON выпуска (`tag_name`, `body`, `assets` с `name`, `browser_download_url` и `size`). Загрузки затем принимаются с того же сервера. На странице Обновления написано, что адрес заменен. Автоматические запуски проверяют только тогда, когда он установлен. |
| `HP_UPDATE_CURRENT_VERSION` | Делает вид, что эта версия установлена (например, `1.0.0`), поэтому любой выпуск выглядит новее. |

Без `HP_UPDATE_API_URL` проверка и загрузки обращаются только к `github.com`, `api.github.com` и хостам загрузки GitHub (`*.githubusercontent.com`) по HTTPS. Перенаправления выполняются по одному (не более 5), и каждый новый адрес должен быть одним из этих хостов, поэтому перенаправление на другой сервер или на обычный HTTP отклоняется. С `HP_UPDATE_API_URL` обычный HTTP принимается только для локального тестового сервера (`localhost` или `127.0.0.1`); любой другой адрес замены должен использовать HTTPS. Кнопка **Открыть страницу выпуска** открывает только страницу GitHub (или локальный тестовый сервер), что бы ни содержал ответ. Архивы больше 1 ГБ отклоняются.

<a id="faq"></a>
## Частые вопросы

**Отправляется ли что-нибудь на GitHub, кроме запроса?** Нет. Это один анонимный запрос на последнюю версию с номером `User-Agent` из `HammerPro/<version>`. Ничего о вас или ваших картах не отправляется.

**Где хранится загрузка?** В `%TEMP%\HammerPro-update-<process>-<tag>`. Старые папки удаляются при более позднем запуске.

**Как мне вернуться?** Закройте Hammer Pro, удалите `hammerpro.exe` и переименуйте `hammerpro.exe.old` в `hammerpro.exe`. Пропустите версию с помощью **Больше не показывать**, чтобы она больше не предлагалась.

**Мне не нужны сообщения об обновлении.** Снимите флажок **Проверять наличие обновлений при запуске**. Вы еще можете проверить вручную.

**Ошибка обновления.** Прочитайте сообщение; журнал помощника находится `update.log` во временной папке `%TEMP%\HammerPro-updater-<process>`. Наиболее распространенными причинами являются антивирус, удерживающий файл и папку без доступа на запись.

<a id="mcp"></a>
## MCP

Помощники AI считывают состояние с помощью `get_update_status` (установленная версия, статус, новейшая версия с примечаниями и контрольной суммой SHA-256, опубликованной для ее архива, прогресс, ошибки, настройки), запрашивают проверку с помощью `check_for_updates`, устанавливают с помощью `apply_update` (требуется `confirm: true`, обнаружено обновление и не выполняется компиляция; он закрывается Hammer Pro, то есть только по запросу пользователя) и замените `update.check_on_startup`, `update.show_dialog` и `update.skipped_version` на `set_setting`. Для действия `install_update` из `run_action` также требуется `confirm`. См. [ссылку на инструмент MCP](../MCP.md).
