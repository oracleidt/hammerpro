# Файлы и папки

Каждый файл и папка Hammer Pro читается или записывается за пределами ваших собственных карт, а также файлов, которые он записывает рядом с ними. Пути указаны для Windows: `%APPDATA%` обычно : `C:\Users\<you>\AppData\Roaming` и `%LOCALAPPDATA%` : `C:\Users\<you>\AppData\Local`.

Автоматические запуски (`--script`, `--screenshot`, `--bench-open`) не записывают ни один из файлов для каждого пользователя, указанных ниже: см. [Командная строка](command-line.md).

<a id="per-user-files-roaming-appdatahammerpro"></a>
## Файлы для каждого пользователя (в роуминге): `%APPDATA%\HammerPro`

| Путь | Что это такое |
|---|---|
| `settings.toml` | Каждая настройка в TOML: одна таблица на область (`[view]`, `[edit]`, `[ui]`, `[game]`, `[compile]`, `[mcp]`...). Записываются только таблицы, отличающиеся от значений по умолчанию, поэтому файл остается коротким. Неизвестные или отсутствующие ключи допускаются, а недопустимый файл заменяется файлом по умолчанию (записывается предупреждение). Его отсутствие означает первый запуск: отображается мастер первого запуска. Ключи: [Ссылка на настройки] (settings.md). |
| `crash\` | Отчеты о сбоях: `crash-<time>.txt` для сбоя редактора, `crash-<time>-worker.txt` для фонового потока, который завершился сбоем, пока редактор продолжал работать. `pending.txt` указывает на отчет, который будет отображаться при следующем запуске, а `running-<pid>.txt` отмечает работающий сеанс (удаляется при обычном закрытии, поэтому сеанс, который завершился без отчета, обнаруживается при следующем запуске). |
| `prefabs\` | Библиотека префабов, в которой пишутся новые префабы. В настройках можно выбрать другую папку (`placement.prefab_library`). |
| `sprinkle\` | Ваши собственные определения посыпки. |

<a id="per-user-files-local-localappdatahammerpro"></a>
## Файлы для каждого пользователя (локальные): `%LOCALAPPDATA%\HammerPro`

| Путь | Что это такое |
|---|---|
| `autosave\` | Автосохранение и экстренное сохранение: `<map>_<hash>_<unix seconds>.vmf`, где хэш идентифицирует полный путь к карте (две карты с одинаковым именем никогда не имеют общего поворота). По умолчанию каждые 5 минут сохраняется 10 копий на карту (настройки `edit.autosave_minutes` и `edit.autosave_keep`, `0` минут отключают автосохранение). |
| `logs\hammerpro.log` | Журнал текущей сессии, записанный построчно. Предыдущий сеанс сохраняется как `hammerpro.old.log`. |
| `mcp\instances\<pid>.json` | Запись каждого окна, на котором включен сервер MCP (порт и секретный токен). Удаляется при остановке сервера. См. [MCP-сервер](mcp-server.md). |
| `maps\<map key>.toml` | Дополнительный файл каждой карты (см. ниже). |
| `thumbs\` | Миниатюры материалов и моделей, которые изготавливаются медленно, сохраняются между сеансами. |
| `prefab_thumbs\` | Миниатюры библиотеки префабов. |
| `pack\` | Кэш файлов, упакованных в скомпилированные карты (конвертированные изображения, извлеченные файлы). |
| `compile_content\` | Созданная папка игры, которая делает ваши пользовательские материалы (папки с пользовательскими текстурами, простые изображения) и пользовательские модели карты видимыми для компилятора. |
| `builds\` | Кэш стадий компилятора: идентичный шаг геометрии или освещения восстанавливается вместо повторного запуска. |
| `content_index.bin` | Сохраненный индекс игры, пользовательских и смонтированных папок, поэтому запускает сканирование только того, что изменилось (см. [Индекс контента и сканирование](../features/content-index.md)). |
| `compile_history\<map key>.jsonl` | Временная история компиляции каждой карты (вкладка «История» окна компиляции). |
| `progressive\`, `spec\` | Сборки прогрессивной компиляции (играйте сейчас) и фоновой прекомпиляции. |
| `untitled\` | Соберите папку карт, которые никогда не сохранялись. |
| `release\<map>\` | Рабочие файлы **Создайте и сохраните как контент**. |
| `propsrc\` | Source файлы моделей, созданных Propper. |
| `decompiled\` | Содержимое, скопированное из скомпилированных карт, открытых с помощью **BSP Decompiler...**. |
| `sniffer\` | Папка вывода по умолчанию для [BSP Sniffer](../features/bsp-sniffer.md) (VMF, BSP, содержимое и отчет каждого запуска; настройка `sniffer.output_dir`). |

Все в этой папке, кроме `autosave\` и `logs\`, является кешем: вы можете удалить его, пока Hammer Pro закрыто, при необходимости он восстанавливается (сопутствующие файлы содержат только удобство, см. ниже).

<a id="the-sidecar-file-of-each-map"></a>
## Дополнительный файл каждой карты

Данные редактора, которые не принадлежат VMF, хранятся для каждой карты в `%LOCALAPPDATA%\HammerPro\maps\<map key>.toml`, где ключом является имя файла карты, за которым следует хеш его полного пути (`untitled` для карты, которая никогда не сохранялась). Он читается, когда карта открывается, и записывается (атомарно), когда карта сохраняется и когда она закрывается. Отсутствующая или поврежденная коляска просто читается по умолчанию: она никогда не является единственной копией вашей работы.

| Раздел | Что он помнит |
|---|---|
| `startup_view` | 3D- и 2D-камеры и активный инструмент восстанавливаются при открытии карты. |
| `workflow` | Точный размер сетки (VMF хранит только целое число для Hammer). |
| `game` | Игра карты (см. [Портировать карту в другую игру](../guides/port-to-another-game.md)). |
| `compile` | Последняя успешная компиляция каждой сборки карты для умной перекомпиляции. |
| `content` | Параметры «Создать и сохранить как контент»: заголовок дополнения, теги, список игнорирования, описание, папка вывода, идентификатор мастерской, последнее примечание об изменении, сводка последнего выпуска, отпечатки навигационной сетки и кубической карты, а также секретная соль рандомизатора материалов Protect your BSP. |
| `health_ignored` | Проблемы, которые вы решили игнорировать. |
| `placement` | Счетчик сборного токена `&i`. |
| `startup_export` | Последний экспорт, для «Экспортировать снова». |

<a id="files-next-to-your-map"></a>
## Файлы рядом с вашей картой

| Путь | Что это такое |
|---|---|
| `<map>.vmf` | Ваша карта. Компиляция никогда не сохраняет его и не изменяет. |
| `.hammerpro_build\` | Папка компиляции: снимок компилируемой карты (`<map>.vmf`, или `<map>_cordon.vmf`, когда компилируется только кордон) и то, что компилятор пишет рядом: `<map>.bsp`, `<map>.log`, `<map>.lin` при утечке карты, `<map>.prt` для запечатанной карты. `.hammerpro_build\portals\` содержит сборки только геометрии **Порталов сборки (только геометрия)**. |
| `<map>.nav` | Навигационная сетка, созданная Hammer Pro (где ее ищут средства просмотра навигационной сетки и функции «Создать и сохранить как контент»). |
| `<map>_content\` | Выходная папка по умолчанию: **Создать и сохранить как содержимое** (можно выбрать другую). |

Когда вы запускаете `hammerpro --bspc` самостоятельно, файлы `.bsp`, `.log`, `.lin` и `.prt` записываются рядом с картой, которую вы ему предоставляете.

<a id="the-build-and-save-as-content-folder"></a>
### Папка «Создать и сохранить как содержимое»

```text
<out>/<addon>/addon.json
<out>/<addon>/maps/<map>.bsp, <map>.nav, thumb/<map>.png
<out>/<addon>/materials/..., models/..., sound/...   (Workshop addon)
<out>/<addon>.gma
<out>/<addon>_icon.jpg
<out>/fastdl/...                                     (server kit)
<out>/.hammerpro_release.toml
```

`.hammerpro_release.toml` : это манифест выпуска: для каждого файла, написанного выпуском, указывается размер и время изменения его источника и записанной копии. Следующая сборка пропускает неизмененные файлы и перезаписывает GMA только при изменении входных данных. Hammer Pro удаляет только файлы, перечисленные в этом манифесте.

<a id="files-in-the-game-folder"></a>
## Файлы в папке с игрой

| Путь | Что это такое |
|---|---|
| `garrysmod\maps\<map>.bsp` | Скомпилированная карта, скопированная туда после компиляции (опция `compile.copy_to_maps`, включена по умолчанию; в `compile.maps_dir_override` можно установить другую папку). |
| `garrysmod\addons\hammerpro_dev\` | Дополнение для разработки: компиляции Draft и Normal не упаковывают ваш пользовательский контент (материалы, модели, звуки, файлы частиц с манифестом частиц карты, скрипты карты) в BSP, вместо этого он копируется в эту папку, поэтому карта выглядит правильно в игре. Копия является инкрементальной и никогда не записывает данные за пределы этой папки. При использовании политики пакетов по умолчанию Final компилирует и выпускает пакет. Настройка `compile.dev_addon` включена по умолчанию. |
| `garrysmod\addons\hammerpro_bridge\` | Аддон моста HammerPro, небольшой файл Lua, устанавливаемый только по запросу (никогда не упаковываемый в карту). Он помещает игрока в камеру после загрузки карты, активирует входные данные и отправляет обратно проп, который вы поместили в игру, для **Импорта пропа из игры**. |
| `garrysmod\addons\hammerpro_livelink\` | Аддон живой связи, один файл Lua, записываемый при запуске [живой связи](../features/live-link.md) (никогда не упаковывается в карту). **Удалить аддон живой связи из Garry's Mod** удаляет его. |
| `garrysmod\data\hammerpro_livelink\` | Файлы сессии живой связи: `session.json` (токен и пульс), `cmd.json` (правки для игры), `game.json` и `ents.json` (ответы игры), `addon.txt` (копия для загрузки в запущенную игру). Удаляются вместе с аддоном. |
| `garrysmod\data\hammerpro\` | Файлы редактора и игры обмениваются через бридж: `cmd.json` (написанные редактором), `ack.json` и `props.json` (написанные игрой). |
| `garrysmod\console.log` | Записывается игрой при включенной опции быстрого запуска `-condebug`; Hammer Pro читает его для отчета о загрузке карты. |

<a id="files-of-the-update"></a>
## Файлы обновления

| Путь | Что это такое |
|---|---|
| `hammerpro.exe.old` | Рядом с программой: версия, замененная последним обновлением, сохраненная в качестве резервной копии (см. [Обновления](../features/updates.md)). |
| `%TEMP%\HammerPro-update-<process>-<tag>\` | Скачанный архив релиза. Удален при более позднем запуске. |
| `%TEMP%\HammerPro-updater-<process>\` | Копия программы, которая устанавливает обновление, и ее `update.log`. Удален при более позднем запуске. |

## Предварительная загрузка ресурсов карты

Перед показом VMF редактор подготавливает материалы, скины и группы тел моделей, спрайты сущностей, грани неба и ссылки на материалы частиц. Каждый завершённый ресурс добавляет одну единицу к счётчику. Процент отражает количество завершённых ресурсов, а не время или объём данных. Ресурс модели включает материалы выбранного скина и группы тел. Последние операции показаны под индикатором. Отсутствующий ресурс завершает обработку с предупреждением, которое сохраняется в консоли.

Отмена во время подготовки сохраняет предыдущую карту. На заключительном этапе карта скрыта до завершения загрузки геометрии и активных зависимостей рендера. Несколько открываемых файлов сохраняют порядок. Защита несохранённых изменений остаётся активной.
