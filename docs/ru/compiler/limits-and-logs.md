# Лимиты и журналы

Ограничения движка, в которых должна оставаться карта, как Hammer Pro их измеряет и как читать журнал компиляции, его пояснения и статистику.

<a id="engine-limits"></a>
## Ограничения двигателя

Собственные инструменты и движок Garry's Mod расширили многие ограничения Valve. Hammer Pro содержит одну таблицу обоих значений (если инструменты и движок Garry's Mod различаются, сохраняется меньшее значение). Компилятор проверяет ограничения [целевой игры](target-games.md): Garry's Mod для Garry's Mod, Source SDK 2013 для других игр. 0 означает отсутствие ограничений.

|---|---|---|
| Модели брашов (объекты брашов, включая мир) | 1024 | 4096 |
| Браши | 8192 | 65535 |
| Стороны браши | 65536 | 655350 |
| Самолеты | 65536 | 65536 |
| Вершины | 65536 | 65536 |
| BSP-узлы | 65536 | 65536 |
| Информация о текстуре | 12288 | 32768 |
| Материалы (texdata) | 2048 | 8192 |
| Дисплейсменты | 2048 | 16384 |
| Грани, оригинальные грани | 65536 | 65536 |
| Листья, лицевые поверхности листьев, браши листьев | 65536 | 65536 |
| Области | 256 | 1024 |
| Ареопорталы | 1024 | 1024 |
| Края поверхности | 512000 | 512000 |
| Края | 256000 | 256000 |
| Примеры кубических карт | 1024 | 1024 |
| Наложения | 512 | 8192 |
| Грани одного наложения | 64 | 64 |
| Грани одного водного слоя | 256 | 256 |
| Огни мира (за проход) | 8192 | 8192 |

| Текст объекта | 384 KB | 4 MB |
| Данные о видимости | 16 MB | 16 MB |

Другие строки (нормали вершин и их индексы, данные о воде листьев, вершины ареапорта, наложения воды, вершины дисплейсмента и треугольники) следуют за той же таблицей и появляются в статистике.

<a id="limit-profiles"></a>
### Предельные профили

В ходе интерактивных проверок и в диалоговом окне **Карта > Информация о карте** карта сравнивается с профилем, выбранным в списке **Пределы:** (сохраненном как `limit_profile` в таблице `[health]` `settings.toml`):

| Профиль | Пределы |
|---|---|
| **Автоматически** (по умолчанию) | Garry's Mod 64-бит для Garry's Mod, Source SDK 2013 для остальных игр |
| **Source SDK 2013** | Значения Valve `bspfile.h` |
| **Garry's Mod 32-битная** | то же, что сегодня 64-битная версия |
| **Garry's Mod 64-битная** | столбец Garry's Mod выше |
| **VBSP++** | Пределы Garry's Mod с 65536 объектами |

Строка состояния и [Проверить наличие проблем](../features/check-problems.md) предупреждают, когда предел близок («Браши: 60000 из 65535 (91%)») и когда он превышен («..., компиляция завершится неудачей»). После каждой компиляции компилятор проверяет написанный им BSP: каждый индекс внутри его блока, каждый счетчик в пределах. Любая проблема : это ошибка компиляции, поэтому компилируемая карта загружается.

<a id="reading-the-compile-log"></a>
## Чтение журнала компиляции

Вкладка **Журнал** в [Окне компиляции и запуска](compile-window.md) показывает каждую строку каждого шага по мере его поступления, с индикатором выполнения для каждого шага. Тот же текст добавляется к `<map>.log`.

- **Цвета и фильтры**: информация, предупреждения и ошибки; **Показать информационные строки**, **Показать предупреждения**, **Показать ошибки**, **Поиск в журнале**, **Автопрокрутка**, **Копировать весь журнал**. Щелкните шаг, чтобы увидеть только его линии; **Показать журнал каждого шага** очищает это.
- **Проблемы с кликабельностью**: строка, обозначающая браш, грань (сторону), объект или положение, становится ссылкой: щелкните ее, чтобы выбрать объект и отцентрировать вид («Нажмите, чтобы перейти к браши 12»). Журнал, принадлежащий другой карте, советует вам сначала открыть его.
- **Список проблем**: «Проблемы: N ошибок, M предупреждений», каждая из которых имеет **Перейти**.
- **Пояснения**: известные сообщения получают простое объяснение и кнопку: **Справка** (страница сообщества разработчиков Valve), **Перейти**, **Путь утечки** (загружает файл точек) или **Проверить** (открывает проверку на наличие проблем).
- **Уведомления о конвейере**: строки, написанные самим Hammer Pro, такие как «Компиляция остановлена после геометрии: утечка карты», «Упаковано N файлов в BSP», «Те же входные данные, что и при предыдущей компиляции: результат используется повторно», «... еще не существует: выполняется полная компиляция вместо частичной», «Не удалось заменить...: если карта загружена в игру, сначала измените карту или отключитесь».
- Сбой шага называется («Программе не хватает памяти», «переполнение стека»...) с кодом завершения.

Компилятор специально печатает формулировку VBSP, поэтому те же правила действуют и в журналах инструментов Valve.

<a id="common-messages"></a>
### Общие сообщения

| Сообщение содержит | Значение | Что делать? |
|---|---|---|
| `**** leaked ****` | Сущность может достичь пустоты через дыру в брашах мира. | Следуйте по пути утечки и загерметизируйте отверстие мировой щеткой (`func_detail` и щеточные объекты не герметизируются). См. [Утечки и файлы точек](../features/leaks-pointfiles.md). |
| `leaked!` | Этот объект является началом пути утечки. | То же, что и выше. |
| `areaportal leak` | Зональный портал не закрывает свое отверстие. | Заставьте пространственный портал заполнить свое отверстие; отделите области брашами мира. |
| `microbrush` | Браш слишком мала или слишком тонка для построения. | Delete или сделайте его толщиной не менее 1 единицы на сетке. |
| `texture axis perpendicular` | Текстура проецируется вдоль собственной грани. | Сбросьте выравнивание грани (проверьте наличие проблем, это исправит). |
| `mixed face contents` | Одна браш смешивает содержимое (воду и твердое вещество, nodraw и зажим...). | Используйте один вид материала на каждом грани. |
| `displacement found on a(n)` | Дисплейсмент внутри объекта браши. В `func_detail` это лишь предупреждение: дисплейсмент компилируется как дисплейсмент мира. | Переместите браш дисплейсмента обратно в мир. |
| `too many switched lights` | Более 96 именованных источников света (32 за пределами Garry's Mod). | Дайте огням, которые переключаются вместе, одно и то же название; удалите имена, которые никогда не переключаются. |
| `must be used on a dynamic entity` | Модель `prop_static` имеет `prop_data`. | Используйте `prop_physics` или `prop_dynamic` или `-AllowDynamicPropsAsStatic`. |
| `must be compiled with $staticprop` | Модель не является статичной опорной моделью. | Используйте `prop_dynamic`. |
| `overlay touching too many faces` | Наложение охватывает 64 или более граней. | Сделайте его меньше. |
| `too many overlays`, `too many brush models` | Превышены лимиты. | Удаление или объединение наложений; превратить объекты браши, которые не перемещаются, в мировые браши или `func_detail`. |
| `could not open instance file` | Файл `func_instance` отсутствует. | Проверьте его путь (относительно карты или папки с картами). |
| `bad surface extents` | Грань слишком велико для его карты освещения, и его нельзя вырезать (`-nosubdiv`). | Увеличьте масштаб карты освещения или разделите браш. |
| `unknown option` | Компилятор не знает опции. | Проверьте правильность написания дополнительных аргументов. |
| `material not found` | Материала нет ни в игре, ни в ваших папках. | Замените его или добавьте его папку в настройках. |
| `error loading studio model`, `outside the map` | Модель пропа отсутствует или сломана, или статический проп находится в пустоте: он удален. | Исправьте путь модели; переместите проп внутри мира. |
| `in solid volume` | Объект находится внутри сплошной браши. | Переместите его на открытое пространство. |
| `findportalside`, `brush with win 0` | Перекрывающиеся или недопустимые браши. | Очистите браши в этом месте. |
| `max_map_brushes`, `max_map_planes`, `max_map_portals` | Жесткий предел. | Объедините браши, сохраните геометрию на сетке, превратите маленькие браши в `func_detail`. |
| `Warning: ... is not supported by the Hammer Pro compiler (ignored)` | Опция Valve, которую этот компилятор не поддерживает. | Ничего; удалите его, чтобы отключить предупреждение. |
| `Warning: Couldn't open texlight file ...` | Легкий файл не найден. | Проверьте `-lights` или `_lightsrad`. |

<a id="the-statistics-tab"></a>
## Вкладка Статистика

На вкладке **Статистика** (также кнопке журнала **Статистика: N подсказок**) считывается статистика, которую компилятор выводит в конце каждого шага. У каждого элемента, которому есть место на карте (браш, грань, кластер, область, проп), есть кнопка **Перейти**.

- **Советы по оптимизации**: ограничения на уровне 75 % и более (более 90 % они воспринимаются как предупреждения, более 100 % игра может отказаться от карты), карта, скомпилированная без видимости (критично, когда на ней есть вода: игра затем рисует воду черной, без преломления, поэтому компилируйте хотя бы с быстрой видимостью), кластеры, которые видят 50 % карты или более, слабая средняя видимость, большая карта без порталов в области, маленькие структурные браши, которые могут быть `func_detail` (самое маленькое имя), статические пропы без расстояния затухания, дисплейсмент по мощности 4, карты освещения, занимающие 90% или более от 2 GB, к которым может обращаться грань, очень хорошие масштабы карт освещения, переключаемые стили почти израсходованы.
- **Ограничения движка**: таблица vbspinfo Valve (используется, максимум, байты, заполненность), самая полная в первую очередь.
- **Геометрия**: размер карты, браши (структурные, детализированные, водные, инструментальные, в брашах), объекты по классам, грани по материалу, дисплейсменты по мощности, области, небольшие структурные браши и пропы без расстояния затухания.
- **Видимость**: режим (быстрый, полный, взят из предыдущей компиляции с теми же порталами, не вычисляется или пропускается из-за утечки карты), кластеры, порталы, листья, видимые кластеры в среднем и максимум, радиус видимости, кластеры, которые видят больше всего.
- **Освещение**: байты карты освещения каждого прохода по отношению к 2 GB, к которым может обращаться грань, люксели, освещение по типу, переключаемые стили, текстурное освещение, освещенные статические и детализированные пропы, образцы окружения листьев, отскоки, грани и материалы с наибольшим количеством люкселей с их масштабом карты освещения.
- **Время этапа** и **Время шагов**.

Если в журнале нет компиляции Hammer Pro, на вкладке об этом написано. Инструмент MCP `get_compile_stats` дает те же данные.

<a id="faq"></a>
## Частые вопросы

**В строке состояния указано, что ограничение не будет выполнено, но компиляция работает.** Текущие проверки представляют собой оценку, выполняемую перед компиляцией; собственный подсчет компилятора является точным. Проверьте профиль в разделе **Карта > Информация о карте**: профиль с более низкими лимитами, чем ваша игра, более строгий.

**Где журнал старой компиляции?** `<map>.log` в папке `.hammerpro_build` рядом с вашей картой хранится каждый запуск; на вкладке «История» сохраняется время.

**Существует ли ограничение на 16 MB световых карт?** Нет. `MAX_MAP_LIGHTING` (16 MB) все еще находится в `bspfile.h` Valve, но ни инструменты Source SDK 2013, ни Garry's Mod VRAD проверяет это (их таблица размеров печатает данные освещения без максимального значения), и движок загружает больше: Valve скомпилированные Garry's Mod карты загружают от 60 до 80 MB карт освещения за проход. Реальным ограничением для каждой целевой игры является смещение карты освещения грани (`lightofs` в `dface_t`), 32-битное число со знаком: после 2 GB за проход грани не могут указывать на свои карты освещения, и игра не может загрузить карту. Там освещение Hammer Pro прекращается с ошибкой; подсказки предупреждают в 90% случаев. Большие карты освещения по-прежнему требуют памяти и времени загрузки, поэтому используйте грубые масштабы там, где тени мягкие.
