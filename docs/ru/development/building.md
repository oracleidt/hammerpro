# Сборка из исходников

Hammer Pro : это рабочее пространство Rust, состоящее из небольших ящиков. На этой странице объясняется, как собрать редактор, запустить его и выполнить тесты.

<a id="requirements"></a>
## Требования

- **Rust 1.95 или новее** (стабильная), установленная с помощью `rustup`. В рабочей области используется версия 2024.
- В Windows : набор инструментов MSVC (по умолчанию `rustup` в Windows). В сборку встраивается сам значок приложения: компилятор ресурсов не требуется.
- Garry's Mod не является обязательным: многие интеграционные тесты используют его, когда он присутствует, и пропускают себя в противном случае.

Компилятор карт является частью рабочей области: инструменты Valve не нужны ни для сборки Hammer Pro, ни для компиляции карт.

<a id="building-the-editor"></a>
## Создание редактора

```bash
git clone <repository URL>
cd HammerPro
cargo build --release -p hammerpro
```

Исполняемый файл : `target/release/hammerpro.exe` (`target/release/hammerpro` в Linux). `hammerpro` является элементом рабочей области по умолчанию, поэтому только `cargo build --release` создает то же самое.

Чтобы запустить его из исходников:

```bash
cargo run                       # starts the editor (dev profile)
cargo run -- path/to/map.vmf    # opens a map
cargo run --release             # release speed
```

В сборке записывается дата, а при проверке git : фиксация, оба показаны в **Справка > О Hammer Pro**. `SOURCE_DATE_EPOCH` отмечен за воспроизводимые сборки.

<a id="profiles"></a>
## Профили

| Профиль | Команда | Использование | Настройки |
|---|---|---|---|
| `dev` | `cargo build`, `cargo run`, `cargo test` | Ежедневное развитие. Ваш код по адресу `opt-level = 1`, все зависимости по адресу `opt-level = 3`, чтобы редактор оставался работоспособным. Только таблицы строк (достаточно для обратной трассировки), без инкрементного кэша. | `opt-level = 1`, `debug = "line-tables-only"`, `incremental = false` |
| `release` | `cargo build --release` | Сборки, которые вы отправляете. | `lto = "thin"`, `codegen-units = 1`, нет отладочной информации |
| `fast` | `cargo build --profile fast`, `cargo test --profile fast` | Итерационные сборки: скорость выпуска во время выполнения, сборка намного быстрее и проще, чем `release`. Вывод в `target/fast/`. | Наследует `release`, `lto = false`, `codegen-units = 16`, `incremental = true` |

<a id="tests"></a>
## Тесты

```bash
cargo test --workspace
```

- Тесты, использующие реальные игровые данные, ищут Garry's Mod и пропускают себя, если он не установлен. Установите `HAMMERPRO_GMOD_DIR` в папку Garry's Mod (ту, которая содержит `garrysmod` и `bin`), если ее нет в том месте, которое ожидают тесты. В тестах GMA читаются предметы Мастерской из `HAMMERPRO_WORKSHOP_DIR`.
- Таблица перевода каждого крейта проверяется на наличие отсутствующих переводов с помощью тестов крейта.
- Перед запросом на включение выполните те же проверки, что и CI:

```bash
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

<a id="build-folders"></a>
## Создание папок

Полная папка сборки занимает несколько гигабайт. Чтобы поместить его на другой диск, установите `CARGO_TARGET_DIR`:

```bat
set CARGO_TARGET_DIR=E:\builds\hammerpro
cargo build --release -p hammerpro
```

Тогда исполняемый файл находится в `E:\builds\hammerpro\release\`. Профили хранят отдельные папки (`debug`, `release`, `fast`), поэтому переключение между ними не приводит к пересозданию всего.

<a id="patched-dependency"></a>
## Исправлена зависимость

`vendor/wgpu-hal` : это wgpu-hal 30.0.1 с одним изменением, используется до `[patch.crates-io]` в рабочей области `Cargo.toml`: в Windows с Vulkan ожидание возврата образа цепочки обмена с экрана длится до 30 секунд вместо одной, поскольку более длительное ожидание рассматривалось как потеря устройства (занятая видеокарта, другая программа или длинный кадр, закрывающий редактор). При обновлении wgpu проверьте, превращает ли новая версия этот тайм-аут в потерянное устройство; если нет, удалите папку и патч.

<a id="linux"></a>
## Linux и macOS

Опубликованные сборки выпускаются только для Windows. В Linux и macOS соберите Hammer Pro самостоятельно командами выше и обновляйте его так же: `git pull`, затем новая сборка. Когда выходит новая версия, окно обновления сообщает об этом вместо предложения установить её.


Рабочая область также построена на Linux (CI выполняет проверки в Windows и Linux). Окно поддерживает как Wayland, так и X11. Пути следуют обычным папкам: настройки в `~/.config/HammerPro`, журналы и автосохранения в `~/.local/share/HammerPro`, кэши в `~/.cache/HammerPro`.

<a id="faq"></a>
## Частые вопросы

**Какой ящик мне собрать, чтобы получить редактор?** `hammerpro` (`crates/hammerpro`), член по умолчанию.

**Сборка выполняется медленно.** Используйте профиль `fast` во время итерации и `--release` только для сборок, которыми вы делитесь.

**Тесты занимают много времени или завершаются неудачей из-за отсутствия файлов игры.** Тесты, которым нужны файлы игры, пропускаются автоматически, если файлы отсутствуют; укажите `HAMMERPRO_GMOD_DIR` на вашу установку, чтобы запустить их.
